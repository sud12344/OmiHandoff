2. METHOD
---------
git merge-file --diff3 (base = the base file), sequentially; every conflict block resolved by hand-chosen rule (merged/_work/resolve3.py,
the exact rule per block is listed below); then a semantic review of every hunk of all four gen_tee diffs against each other (sections 4);
semantic fixes applied by merged/_work/semfix.py (asserted exact replacements). Order: gen_tee = perlegsw (ours) + hoseb -> + flange -> + angled;
gen_straight2 = straights (ours) + flange; dofcheck_tee = flange (ours) + hoseb (clean) -> + angled. Intermediates kept in merged/_work/.
merged/_work/feature_lines_check.txt: every line a feature ADDED is verbatim in the merged file, except exactly the lines changed by the
resolutions below (24 lines, all listed there).

4. SEMANTIC CONFLICTS (no textual conflict - found in the hunk-by-hunk review; fixed in merged/_work/semfix.py)
---------------------------------------------------------------------------------------------------------------
 S1 PERLEGSW x HOSEB: hoseb_endlib fills the ORB tokens into a COPY of the row and writes their source into the warnings first ($COMMENT order);
    with perlegsw merged, end_val would read the same tokens again and append the same two warnings a second time at the leg (4601 / 4603
    $COMMENT changed). hoseb's note "hoseb_endlib stays harmless" holds for the values, not for the text. Fix: end_val returns r[c] without a
    warning when the row copy already carries the token (`if c in r: return r[c]`). 4601 / 4603 = hoseb's output exactly (proof 1).
 S2 FLANGE x PERLEGSW: flange's row gate `if any(kind in FLG_KINDS for (kind, lc, bc, tc) in sp['legs'])` runs for EVERY root and unpacks 4-tuples:
    ValueError on every perleg root (5-tuple legs: 6807, 6606, 1601, 1602, 1603) - the whole root would stop. Fix: legs4(sp) in the three
    flange lines (gate, flg_o loop, miss_ list); identical result on 4-tuple SPECs.
 S3 HOSEB x PERLEGSW: the same 4-tuple unpack in hoseb_endlib, the hose-bore gate (_hb) and the HOSEB AxialSource text (_hl). Only hose roots
    reach them today; legs4(sp) keeps them safe if a hose root ever gets a 5th leg element. No output change.
 S4 ANGLED x HOSEB: angled_texts / angled_help / helixu_check read L['thread']['type'] for every leg on the 135 deg axis; on 4603 / 4503 that leg
    is the HOSE leg with thread None -> TypeError (both roots would stop). Fix: (L['thread'] or {}).get('type') == 'HELIX' (a leg without
    a thread is not a helix leg). The emit thread loop already skips thread None before the angled branch (C7).
 Checked, no conflict: gen_tee reads gen_straight2 (G.NPTF / ENDL / FPT / ORB / end_FLG61 / end_FLG62 / flg62_head / end_HOSEB / lib_gaps):
    the straights additions (dash 40, ORBF_MEAS[2], 6400) and the flange additions change no tee root (proofs 1, 1b, 2); angled's MakeLegPlane
    Mtip change, 135-deg NPTFF / swivel / helix emit branches and e45 checks never see a HOSEB or FLG leg as a helix / port / swivel; flange's
    flange-leg `continue` in the geometry checks skips hoseb's arm-clearance tweak; DataStatus blocks (NPSM / HOSEB / FLG) are independent; the
    perlegsw ENDLIB AxialSource sentence reads only 5th-element tuples (none on hoseb / angled SPECs).
